# IAM Threat Model & Mitigations

| Threat Vector                         | Description                                                      | Community OS Mitigation                                                                                                                                                                            |
| :------------------------------------ | :--------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Token Replay / Hijacking**          | An attacker steals an access token and replays requests.         | Access tokens have a short 15-minute TTL. Active sessions can be instantly revoked server-side, rendering all associated access tokens invalid immediately.                                        |
| **Refresh Token Exfiltration**        | An attacker steals a refresh token.                              | Refresh token rotation ensures that each token is single-use. The database only stores SHA-256 hashes of refresh tokens, preventing leakages from database dumps.                                  |
| **Cross-Tenant Lateral Movement**     | An admin of Org A attempts to view or modify resources in Org B. | `evaluateScopedPermission()` strictly verifies that the actor's scoped role assignment matches the resource's `organizationId` or `communityId`. Failures result in fail-closed 403 access denial. |
| **Privilege Escalation**              | A tenant admin attempts to assign `PLATFORM_ADMIN` to self.      | `RoleAssignmentsService` enforces that only callers with `isPlatformAdmin: true` can assign `PLATFORM` scope or system platform roles.                                                             |
| **Credential Stuffing / Brute Force** | High-frequency password guess attempts.                          | Passwords hashed with bcrypt cost factor 12. Account suspension locks account before password comparison. Inactive sessions automatically expire.                                                  |
| **Tampered JWT Claims**               | Client modifies claims (e.g. changing `isPlatformAdmin`).        | JWTs are cryptographically verified against a high-entropy secret; `AuthGuard` re-verifies session status against the live database on every request.                                              |
